# Rename checklist

`ProductName` (`Sources/SiftCore/ProductName.swift`) carries the binary name, the state directories, the config file, the backup suffix, the MCP server and tool prefix, the environment-variable prefix and the rule file name. A rename sets it once (`Docs/Design.md` §6.10 says what the code then does with old state). What follows is what the constant cannot cover and a rename still changes by hand.

## Packaging

- The Homebrew formula template, `Distribution/homebrew/swift-sure.rb`: `bin.install` names the binary. The command links for each legacy name and alias are generated by `Distribution/homebrew/build.sh` from `install.sh`'s `LEGACY_NAMES` and `ALIAS_NAMES`; the script's two `swift-sure` literals (the `bin.install_symlink \"swift-sure\"` line at `:43` and the `bin.install \"swift-sure\"` anchor the links are inserted under at `:53`) are changed by hand, and the build fails when the template holds no such anchor. The tap formula's own name changes with it.
- The historical npm package name, `ProductName.npmPackage`: it does not follow a rename, since uninstall uses it to recognise an entry made through `npx` by an earlier release.
- The Claude Code plugin and marketplace names (`Distribution/mod/`, and the references in `Distribution/install.sh` and `Distribution/INSTALL.md`).

## Docs

- The agent guide `SwiftSure.md` and its installed copy in `~/.claude/rules/`, the `SwiftSure.docc` catalogue, and the README, Guide, Design and CHANGELOG prose.

## Code names

- Swift module and type names (`SiftCore`, `SiftPaths`, and the rest) are internal and may stay.
- Doc comments that spell the name are not routed through the constant.
- Messages that still hard-code the name, in the uninstall notes (`Sources/SiftCore/SiftUninstall.swift`).
- `GitContext.cacheIsExcluded` and the `.git/info/exclude` entry cover only the current directory name; `leftCaches` lists only the resolved home directory.
- The self-defined replay payload keys stay unchanged on purpose: transcripts written earlier carry them.

## Other tools

- swift-fieldwork recognises hooks by binary basename; SwiftSure passes a `FieldworkTool` per legacy name (`SiftClaudeSetup.hooks(recognising:)`) so those are removed.
- The library's `installedRuleName` and backup extension are set there, and a test pins them against `ProductName.ruleFileName` and `backupSuffix`.

## Lists and tests

- `Distribution/public-names.txt`, `Distribution/example-names.txt` and `Distribution/private-terms.txt`.
- Tests that assert literal output spell the name.
- `Benchmarks/` scripts and results name the binary.

## Distribution scripts

- `make-dist.sh` (its binary name and staging directory), `cut-public-repo.sh`, `verify-tree.sh`, `homebrew/build.sh`, `release-notes.sh` and `agent-parity.sh`.
- The registry name (`io.github.Agulhas-Labs/<product>`, `registry-files.sh`) and the marketplace name (`<product>-plugins`, `marketplace-file.sh`, called by `cut-public-repo.sh`) follow the product word.
- `install.sh`: the `SWIFT_SURE_DEST` and `SWIFT_SURE_HOME` variables, the `.swift-sure` literals, and the `SwiftSure.md` source name. Its `NAME` and `LEGACY_NAMES` are set by the flip below and pinned by a test against `ProductName`.

## External names

- The GitHub repository names.

## The flip

1. Set `ProductName.current` to the new name and move the old word to `legacy`.
2. Set `install.sh`'s `NAME`, `LEGACY_NAMES` and `ALIAS_NAMES` to match, and `ProductName.aliases` with them.
3. Only if the rename installs the agent rule under the display name rather than the binary's (`swift-sure.md` today, the library's `installedRuleName`):
   - change the library's `installedRuleName`;
   - take `LegacyRegistrationCleanup`'s current-rule path (`rules.appendingPathComponent("\(current.binary).md")`) from the library;
   - change `install.sh`'s `$RULES/$NAME.md` (the rule copy and its symlink check);
   - update both pins: `RenameMigrationStateTests.theBackupSuffixAndRuleFileNameMatchWhatTheLibraryWrites` (`ProductName.current.binary + ".md" == installedRuleName`) and `SiftClaudeSetupTests` (`== "swift-sure.md"`).

   Each legacy rule keeps `<legacy binary>.md`, the name that release installed.
4. `Distribution/plugin/` is regenerated from the renderer (run `PluginFilesTests`; its failure prints each file).
5. Release.
6. One release later, empty `legacy`.
